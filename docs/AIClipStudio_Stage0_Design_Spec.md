# AIClipStudio Stage 0 設計方針

- 対象: `rose4320/AIClipStudio`
- 対象コード: v0.4 / Vanilla HTML・CSS・JavaScript の単一HTMLアプリ
- 状態: 設計・調査段階。アプリ本体の実装変更は未実施
- この文書の目的: 既存データを保全しながら、漫画制作・ストーリー制作・AI支援を段階的に統合するための設計基準を共有する。

## 1. 基本原則

1. 既存の作品・シーン・アセット・画像を失わない。
2. データ移行は冪等とし、何度実行しても重複・破壊しない。
3. AIは提案を行い、作者の承認なしに確定設定・脚本・原稿を変更しない。
4. 確定設定、作者の仮案、AI提案、AI推測を明確に区別する。
5. 作品ごとにコンテキストを分離し、別作品の情報混入を防ぐ。
6. iPad Safariを第一対象とし、メモリ・ストレージ制約を考慮する。
7. クラウドAIを先行可能にし、将来ローカルAIを接続できる構造にする。
8. 実装はStageごとにテストし、各段階で作者の確認を得る。

## 2. 現行実装の確認事項

- ルートの `index.html` にHTML/CSS/JavaScriptが集約されている。React/Next.js構成ではない。
- localStorage keyは `aiclip_v02`。主要データは `projects`, `current`, `assets`。
- Projectには `id`, `title`, `genre`, `world`, `synopsis`, `scenes` 等がある。旧 `sceneTitle` / `sceneBody` との互換処理がある。
- IndexedDBは `AIClipStudioAssets` v1、Object Store `images`。画像BlobをアセットIDで保存する。
- 現在のJSONバックアップはIndexedDB画像Blobを含まない。
- 画像差し替え時に過去Blobの版管理はなく、削除後に孤立画像が残る可能性がある。
- 描画はCanvas 860×1214、5レイヤー名をstroke属性として扱う試作。描画配列はメモリ上のみで永続保存されない。
- 消しゴムは白色上書き方式。Undoは簡易版でRedoは未確認。
- AIストーリー支援、画像AI、画像を含む完全バックアップ、高解像度原稿出力は未実装。
- READMEの説明はv0.2のままで、現行実装との乖離がある。

## 3. 原稿規格: 作品単位管理（作者確認済み）

原稿規格は**作品単位で1つ**管理し、作品内のすべてのページに適用する。ページごとに異なる原稿サイズ・解像度を設定する機能は設けない。

### 対応方針

- 出版社・印刷会社ごとの原稿規格をプリセットとして登録できる。
- Web漫画、モノクロ漫画、カラー漫画、同人誌・印刷用などの用途別プリセットを用意できる。
- 作者が幅・高さ・単位（px/mm等）・DPI・塗り足し・仕上がり領域・安全領域を指定するカスタム規格にも対応する。
- 特定の出版社・印刷会社の仕様に固定しない。
- 4299×6071px / 600dpiは初期候補であり、全作品に強制しない。

### 制作開始後の規格変更（作者確認済み）

作品設定から、制作開始後でも原稿規格を変更できる。変更は作品内の全ページに一括適用する。

変更前に自動バックアップと影響プレビューを行い、少なくとも次の選択肢を提示する。

1. **キャンバスと描画を比例変換**: 新しい寸法に合わせる。補間・切り取り・画質低下の可能性を事前表示する。
2. **キャンバス範囲のみ変更**: 描画サイズを維持し、余白追加または切り取り範囲を調整する。
3. **キャンセル**: 変更しない。

元の描画データは非破壊で保持し、変換前後の規格と変更履歴を保存する。可能な限り規格変更操作をUndo/復元できるようにする。ピクセル寸法・物理寸法・DPIを混同しない。ページデータ自体に独立したwidth/heightを持たせず、作品のCanvasProfileを参照させる。

推奨データ概念:

```json
{
  "canvasProfile": {
    "presetId": null,
    "width": 4299,
    "height": 6071,
    "unit": "px",
    "resolutionDpi": 600,
    "bleed": {
      "top": 0, "right": 0, "bottom": 0, "left": 0,
      "unit": "mm"
    },
    "trimArea": null,
    "safeArea": null,
    "version": 1
  }
}
```

## 4. 目標データ構造

既存Project / Scene / Assetを維持し、段階的に以下を追加する。

- **StoryBible**: 作品の根幹設定、テーマ、世界観ルール、確定設定、仮案。
- **CharacterProfile**: 性格、動機、恐れ、口調、外見固定特徴、成長、確定状態。既存Assetとは任意連携。
- **Relationship**: 人物間の関係と適用時期。
- **TimelineEvent**: 作中時間順の出来事。
- **PlotOutline / Arc**: 全体構成、章・話の目的、山場。
- **PlotThread**: 伏線・謎、提示シーン、回収シーン、状態。
- **Page / Layer / DrawingOperation**: ページ、5レイヤー、ベクター描画操作。
- **AssetImageVersion**: 画像差し替え時に旧Blobを保持する版管理。
- **AIProposal / AIReview**: AIの提案、根拠、採否、矛盾チェック、履歴。

5レイヤーの表示順（上から）:
1. セリフ・吹き出し
2. 効果・演出
3. コマ
4. 人物
5. 背景

## 5. データ保全・描画エンジン

- 既存localStorage key `aiclip_v02` を移行元として維持する。
- IndexedDB v1の `images` storeを削除・改名しない。バックアップと回帰テスト後に必要なstoreを追加する。
- 移行前バックアップ、読み取り解析、新構造コピー、ID・件数・参照整合性検証、保存、回帰テストの順で行う。
- 移行バージョンを記録し、二重適用を防ぐ。ID衝突を自動上書きしない。
- ベクターstrokeを正本とし、表示用プレビューと高解像度出力を分離する。
- 消しゴムは白色塗りではなく、erase operation / mask方式を採用する。
- Autosaveは入力確定・入力停止後・ページ切替前などに行い、IndexedDB transaction完了後に保存済み表示とする。
- Undo/Redoは操作履歴方式とする。
- Pointer Eventsを維持し、Apple Pencil筆圧・傾き、pointercancel、指操作、パームリジェクション、DPR座標変換を検証する。
- 画像を含む完全バックアップはZIPパッケージとし、manifest・データ・画像Blob・描画・AI履歴を含める。復元前にサイズ・MIME・ハッシュ・スキーマ・参照整合性を検証し、失敗時は既存データを維持する。

## 6. AIストーリー支援

### 対象機能

- 企画・あらすじ: アイデア整理、複数案、タイトル、テーマ。
- 長編構成: 章・話の役割、起承転結、伏線、山場、次話への引き。
- キャラクター: 人物像、口調、行動原理、成長、関係性。
- 脚本: シーン案、セリフ、会話テンポ、冗長箇所。
- 漫画化: コマ割り、構図、視点、表情、動作、吹き出し量。
- 設定監修: 時系列、口調、性格、世界観、伏線回収、説明不足の確認。

### AIの安全な提案フロー

AI依頼ごとに必要な作品データだけをContext Builderで抽出する。例えば特定人物の行動を検討するときは、StoryBible、人物設定、関連人物、過去登場シーン、対象話前後のプロット、時系列、伏線を参照する。

AI出力はAIProposalとして保存し、`pending` / `accepted` / `accepted_with_edits` / `rejected` / `deferred` で管理する。採用前に差分を表示し、作者の承認なしに確定設定や本編を書き換えない。AIReviewは根拠となる設定・シーンを示し、根拠不足の場合は「判定できない」とする。

AI Gateway（バックエンド）、Context Builder、Prompt/Policy Versioning、Provider Adapterを設ける。APIキーをクライアントへ埋め込まない。外部送信する作品テキスト・設定・画像の範囲を作者が確認・選択できるようにする。クラウドAI先行、ローカルAIは将来追加可能な設計とする。

## 7. Stageロードマップ

- **Stage 0**: 現状調査・統合設計・作者確認。
- **Stage 1**: データ保全、IndexedDB拡張、画像版管理、画像を含む完全バックアップ。
- **Stage 2**: 永続化する5レイヤー編集エンジン、Autosave、Undo/Redo。
- **Stage 3**: StoryBible、CharacterProfile、Relationship、Timeline、Plot管理。
- **Stage 4**: AIストーリー支援v1（企画・あらすじ・構成・人物案、提案・承認）。
- **Stage 5**: 脚本AI、漫画化支援、矛盾・伏線チェック。
- **Stage 6**: 画像AI、高解像度出力、クリスタ出力、ローカルAI、iPad実機総合検証。

- コード変更前に対象コードと影響範囲を再確認する。
